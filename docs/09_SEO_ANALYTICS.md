# 09_SEO_ANALYTICS.md — SEO-аналитика и рост

Чтение данных Яндекс.Метрики и Google Search Console, поиск материалов с
потенциалом роста, предложения владельцу. Это не автопереписывание сайта.

**Как читать этот файл.** «Реализовано» описано по коду. «Запланировано» —
намерение из `PROJECT.md`, в коде отсутствует. При расхождении верить коду.

Файл: `app/services/seo_analytics.py`; UI: `app/api/dashboard.py`,
`app/templates/dashboard/seo.html`.

---

## 1. Реализовано

### 1.1 Источники чтения аналитики

**Яндекс.Метрика.** Reporting API, готовый OAuth-токен и номер счётчика сайта (счетчик `106439629`).
Собирает визиты, просмотры (12 000+ просмотров), пользователей (15 000+ уникальных), отказы, среднюю длительность визита,
долю новых посетителей. Защищена 15-минутным in-memory кешем и retry-механизмом на случай HTTP 429. Отдельно опрашивается счетчик Дзена.

**Яндекс.Вебмастер.** REST API v4, OAuth-токен и хост `https:svodka.press:443`.
Считывает ИКС сайта (SQI = 10), количество страниц в поиске Яндекса (8 541 стр.), выгружает поисковую аналитику (`query-analytics/list`) с реальными показами, кликами, позициями и посадочными URL, а также топ фраз (`search-queries/popular`). Посадочные страницы Яндекса объединяются с GSC в единый пул поиска.

**Google Search Console.** Клиент поисковой аналитики по страницам и запросам через
сервисный аккаунт/JWT: клики, показы, CTR, средняя позиция.

**Сквозная база запросов.** Поисковые фразы Яндекса и Google объединяются в единый реестр (494+ активных фраз) с цветовой маркировкой источника и сортировкой по показам.

### 1.2 Очередь кандидатов на улучшение

Система ищет статьи, которым есть смысл помочь, а не все подряд:

| Параметр | Значение |
| --- | --- |
| Окно отчёта | 28 дней |
| Минимум показов | 10 |
| Плохой CTR | ниже 3% |
| Размер очереди | до 25 статей |
| Таймаут API | 45 секунд |

Позиция и CTR оцениваются вместе: смысл править есть у страницы, которую уже
видят, но по которой не кликают. Кандидаты сортируются по потенциальному
приросту кликов.

### 1.3 Панель

Страница `/seo` показывает отчёт Метрики и очередь. Кнопка «оптимизировать»
сейчас пересчитывает очередь, логирует запрос и показывает список — она
**ничего не ставит в очередь и ничего не меняет**. Это намеренно честное
ограничение, пока не утверждён путь правки живого WordPress-поста.

### 1.4 Что реально включено на проде

Ключи Метрики и Search Console по умолчанию пусты. При вводе данных в панели настроек модуль использует зашифрованные креды из базы данных (`system_settings`).

### 1.5 Подключение и диагностика сервисов Яндекса (`yandex_connection.py`, `dashboard.py`)

Централизованная интеграция сервисов экосистемы Яндекса реализована в `app/services/yandex_connection.py`:
- **Wordstat**: поддержка двух режимов авторизации — прямой Wordstat API (OAuth-токен) или Yandex Cloud Search API (API-ключ + Folder ID).
- **Яндекс.Метрика**: раздельные номера счётчиков для основного сайта (`metrika_counter_id`) и канала Яндекс Дзен (`metrika_dzen_counter_id`) с общим OAuth-токеном аккаунта для получения раздельной статистики посещаемости.
- **Яндекс.Вебмастер**: Host ID сайта (`https:domain.ru:443`) и OAuth-токен для мониторинга индексации и поисковых запросов.
- **Безопасность**: все секретные токены и ключи шифруются симметричным шифром Fernet и сохраняются в БД (`system_settings`, ключ `yandex_services_connection`). При отсутствии записи в БД используется прозрачный фоллбек на переменные `.env`.
- **Диагностические зонды**: функции `probe_yandex_wordstat()`, `probe_yandex_metrika()`, `probe_yandex_metrika_dzen()`, `probe_yandex_webmaster()` выполняют легковесные проверочные запросы к соответствующим API, валидируют корректность токенов и возвращают подробные диагностические сообщения.
- **Интерфейс в `/settings`**: выделенная Bento-карточка с индикаторами статуса каждого сервиса (зелёный/серый/янтарный), полями ввода счётчиков сайта и Дзена, и кнопками мгновенного тестирования связи без перезагрузки страницы («Проверить сайт», «Проверить Дзен») с локальным выводом результатов под каждым блоком.
- **Интерактивная справка по подключению**: сворачиваемое трёхколоночное Bento-руководство со ссылками на OAuth-консоль, Метрику и Yandex Cloud, точными именами прав доступа (`metrika:read`, `metrika:write`, `webmaster:verify`, `webmaster:hostinfo`, `yc.search-api.execute`), инструкцией по подключению счётчика Дзена и пошаговым планом для оператора.

### 1.6 Подключение Google Analytics 4 и Google Search Console (`google_connection.py`, `dashboard.py`)

Централизованное подключение сервисов Google:
- **Google Analytics 4**: чтение посещаемости через GA4 Data API v1beta (`:runReport`).
- **Google Search Console**: статистика поисковых запросов, кликов и показов через Webmasters Search Analytics API с поддержкой строгого ISO-формата дат (`YYYY-MM-DD`).
- **Авто-определение доменных ресурсов GSC**: функция `resolve_gsc_site_url` опрашивает `sites.list()` сервисного аккаунта и сопоставляет ввод обычного домена (`svodka.press`) с зарегистрированным доменным свойством (`sc-domain:svodka.press`) с автоматическим сохранением подтверждённого идентификатора в БД.
- **Service Account RS256 JWT**: генерация Bearer-токенов в памяти без тяжелых библиотек Google Cloud с автокэшированием на 55 минут.
- **Шифрование Fernet**: ключи и сертификаты сервисного аккаунта хранятся в зашифрованном виде (`system_settings`, ключ `google_services_connection`).
- **Интерфейс и справка в `/settings`**: выделенная Bento-карточка с локальными тестами `probe_google_analytics` и `probe_google_search_console`, а также пошаговое руководство по созданию Service Account и выдаче ролей Читателя/Пользователя.

### 1.7 Bing Webmaster Tools и протокол IndexNow (`bing_connection.py`, `lab_pipeline.py`, `publisher_worker.py`)

- **Bing Webmaster API**: 32-значный ключ API, проверка подключённых сайтов через `GetUserSites`.
- **Протокол IndexNow**: мгновенная отправка URL свежеопубликованных статей на моментальную индексацию сразу во все поддерживающие поисковые системы (Bing, Yandex, Seznam, Naver).
- **Автоматический триггер при публикации**: при выходе статьи в свет (через плановый `publisher_worker` или вручную через кнопку публикации в Лаборатории) сформированный канонический URL немедленно отправляется в IndexNow API без задержки и блокировки основного потока.
- **Интерфейс и справка в `/settings`**: отдельная Bento-карточка с диагностикой Bing и IndexNow и инструкцией по размещению ключа в корне сайта WordPress.

### 1.8 Самообучаемая система SEO-оптимизации сниппетов (Low-Hanging Fruits) (`seo_learning.py`, `wp_publisher.py`, `dashboard.py`)

Реализован замкнутый цикл умной оптимизации поисковой видимости на основе реальных данных:
- **Выявление «быстрых побед»**: анализ данных Google Search Console за 28 дней, отбор страниц с высоким числом показов (>50), позицией в топ-5..топ-20 и проседающим CTR (<3%).
- **ИИ-генерация сниппетов с учётом базы выученных побед**:
  - Модель `SeoOptimization` в PostgreSQL хранит снимки до/после: клики, показы, CTR, среднюю позицию, старые и предложенные SEO-Title, SEO-Description, Focus Keyword, обоснование и статус (`draft`, `applied`, `evaluating`, `winner`, `neutral`, `loser`).
  - База знаний: при генерации новых вариантов система извлекает из БД успешные кейсы (`is_winner = true`), подаёт их модели как few-shot примеры, запоминая, какие паттерны формулировок дают максимальный прирост кликов.
- **Интерактивный пульт оптимизации на `/seo`**:
  - Кнопка «⚡ Оптимизировать» открывает модальное окно Split-Comparison: исходные и улучшенные метаданные, превью поискового сниппета Google/Yandex, формулировка гипотезы и обоснование.
  - Оператор может отредактировать заголовок, описание и ключевое слово прямо в модальном окне перед утверждением.
- **1-Click применение в WordPress и IndexNow**:
  - `POST /api/ui/seo/apply/{id}` обновляет метаданные плагина Rank Math (`rank_math_title`, `rank_math_description`, `rank_math_focus_keyword`) через WordPress REST API (`WPPublisherService.update_post_seo_snippet`).
  - Мгновенно отправляет обновлённый URL в IndexNow API, инициируя внеочередной переобход поисковыми ботами Bing, Yandex и партнеров.
  - Фиксирует дату применения и переводит запись в статус `applied`, планируя сбор контрольных метрик через 14 дней.
- **Сквозное влияние Базы знаний на генерацию всех новых статей (`content_worker.py`, `lab_pipeline.py`)**:
  - Метод `get_learned_patterns` синтезирует выигрышную длину Title/Description (на основе реальных побед с ростом CTR > +0.5%), фокусные ключевики в первой трети, фактологические маркеры и таргетинг активных рекламодателей из `/ads`.
  - Эти правила автоматически инжектируются в промт генератора (Writer) как при фоновой авто-генерации статей воркером (`_prepare_studio_aligned_payload`), так и при ручной генерации в Лаборатории (`run_cluster_generate_step`), обеспечивая самообучение всей системы от побед в поиске.
- **История изменений и аудит решений**:
  - Таблица на `/seo` отображает полную хронологию всех принятых оптимизаций: метрики до/после, дельту CTR, выученный статус и прямые ссылки на статьи.

### 1.9 Анализ читательских предпочтений (Сайт vs Дзен) и предиктивный скоринг рекламы для `/ads` (`audience_analytics.py`, `audience_metric.py`, `dashboard.py`)

Создан полноценный фундамент для будущей страницы автоматизированного таргетинга рекламы `https://svodkanews.team-big.ru/ads`:
- **Агрегация мультиканального трафика**:
  - **Сайт (Метрика)**: параллельный опрос Reporting API по срезу путей первого уровня (`ym:s:startURLPath`), визитам, уникальным посетителям, отказам и времени чтения.
  - **Дзен (Метрика Дзен)**: сбор статистики просмотров и читателей по отдельному счётчику канала (`metrika_dzen_counter_id`).
- **Автоматическое профилирование 20 рубрик**:
  - Функция `_extract_category_slug_from_path` сопоставляет URL-структуру `svodka.press/<category_slug>/<post_slug>/` с 20 редакционными категориями, рассчитывая точную долю аудитории каждой рубрики.
- **Алгоритм Ad Potential Index (0.0 — 100.0 баллов)**:
  - `Volume Score (0-35)`: относительный объём аудитории рубрики в выборке.
  - `Engagement Score (0-35)`: глубина чтения (оптимум 120+ сек) и удержание (минимизация отказов).
  - `Commercial Intent (0-30)`: рыночный вес тематики по ставкам eCPM (IT, AI, финансы, недвижимость, медицина).
  - Присвоение уровня готовности: `high` (60+), `medium` (40-60), `low` (<40).
- **Накопление истории в PostgreSQL**:
  - Таблица `audience_category_metrics` сохраняет регулярные снимки по всем 20 рубрикам (`pageviews`, `visitors`, `avg_time_on_page`, `bounce_rate`, `audience_share`, `top_keywords`, `ad_potential_score`, `ad_readiness_level`, `ad_recommendation`), что формирует исторический массив для автоматического назначения рекламы алгоритмом ИИ.
- **Интерфейс на `/seo`**:
  - Вкладка «👥 Читатели: Сайт vs Дзен & /ads» с Bento-сравнением каналов, карточками топ-рубрик для монетизации, стратегическим резюме ИИ и интерактивной таблицей всех 20 направлений.

### 1.10 Замкнутый контур обучения `/seo` по целям рекламодателей (`/ads` ↔ `/seo` Closed-Loop Conversion Learning) (`promoted_projects_service.py`, `seo_learning.py`, `dashboard.py`)

Реализована прямая связка между модулем рекламодателей `/ads` и модулем поисковой и читательской аналитики `/seo`:
- **Окно подключения Яндекс.Метрики и целей у каждого рекламодателя (`/ads`)**:
  - На каждой карточке рекламодателя (например, `FreeAPI AI`, `OutVPN`) выводится блок «Яндекс.Метрика рекламодателя и цели конверсий» и модальное окно `📊 Метрика и цели` (`#metrika-modal-{{ proj.id }}`).
  - Поддерживается ввод `Counter ID`, персонального `OAuth-токена` (с Fernet-шифрованием `SecretBox` и фоллбеком на общий токен Яндекса из `/settings` при гостевом доступе), настройка `utm_source` / `utm_medium` / `utm_campaign` и списка целей конверсий (`ConversionGoal`: `goal_id`, `name`, `target_cr_pct`).
  - **Авто-загрузка целей из API Метрики (`POST /api/ui/ads/{project_id}/metrika/discover`)**: метод `PromotedProjectsService.discover_client_metrika_goals` обращается к Management API Яндекс.Метрики (`/management/v1/counter/{id}` и `/management/v1/counter/{id}/goals`), подтягивая имя счётчика, домен сайта и все настроенные на сайте рекламодателя цели конверсий.
  - **Живая диагностика визитов и целей (`POST /api/ui/ads/{project_id}/metrika/probe`)**: метод `fetch_client_metrika_stats(..., include_counter_totals=True)` сверяет целевые визиты с наших площадок через расширенную атрибуцию (UTM-метки `svodkapress`, `web`, `dzen`, `tg`, `vk`, `ok`, `tenchat`, реферальные токены и пути из `target_url` через `startURLPathFull`, и домены перехода `referer=@'svodka.press'`) и общие визиты/конверсии на сайте рекламодателя за 28/30 дней.
- **Сводный отчёт конверсий и обучение `/seo` (`collect_advertiser_campaigns_report`)**:
  - На странице `/seo` (вкладка «👥 Читатели: Сайт vs Дзен & /ads») отображается панель **«🎯 Целевые визиты и срабатывание целей рекламодателей (Closed-Loop Learning)»** с разбивкой по каждому рекламодателю (визиты по UTM и реферальным ссылкам, всего на сайте, срабатывание каждой цели `ym:s:goal<ID>reaches`, CR%, отказы, время на сайте, индекс качества кампании `CQI` по `evaluate_campaign_quality`).
  - Метод `SeoLearningService.get_learned_patterns` автоматически обогащает правила генерации сниппетов и нативных интеграций данными об активных целях рекламодателей и решаемых болях аудитории, чтобы система училась привлекать максимум целевых визитов и конверсий.

### 1.11 Полная поисковая синхронизация: Яндекс.Вебмастер (Recrawl & Sitemaps), Google URL Inspection & GA4, Синдикационные XML-фиды (`yandex_connection.py`, `google_connection.py`, `feeds.py`, `dashboard.py`)

Реализован полный арсенал поискового продвижения и контроля индексации в поисковых системах:
- **Яндекс.Вебмастер: Очередь приоритетного переобхода роботом (Daily Recrawl Queue)**:
  - Метод `get_yandex_recrawl_quota` опрашивает суточную квоту (150 URL в сутки).
  - Метод `recrawl_yandex_url` отправляет любой URL в приоритетную очередь обхода (`POST /v4/user/{id}/hosts/{host_id}/recrawl/queue`).
  - **Автоматическая связка с AI-сниппетами**: при сохранении оптимизированного Title/Description в WordPress статья мгновенно уходит не только в IndexNow, но и в очередь переобхода Яндекс.Вебмастера.
  - **Ручная отправка на `/seo`**: форма мгновенной отправки любого URL с отображением остатка квоты.
- **Яндекс.Вебмастер: Карты сайта и Диагностика проблем**:
  - Методы `fetch_yandex_sitemaps` и `add_yandex_sitemap` считывают статус обработки XML-карт роботами и позволяют добавлять новые sitemaps в Вебмастер.
  - Метод `fetch_yandex_diagnostics` собирает активные проблемы сайта из Вебмастера (зелёный статус при отсутствии санкций и ошибок индексации).
- **Google Search Console: Инспекция URL в реальном времени (URL Inspection API)**:
  - Метод `inspect_google_url` обращается напрямую к `searchconsole.googleapis.com/v1/urlInspection/index:inspect`.
  - Возвращает живой статус страницы: вердикт робота (`PASS`, `FAIL`), статус покрытия (`coverageState`), дату последнего обхода, состояние `robots.txt` и индексации.
  - Интерактивная форма проверки доступна на вкладке `🔍 Google URL Inspector & GA4` на `/seo`.
- **Google Analytics 4: Сводка аудитории в реальном времени**:
  - Метод `fetch_ga4_report` запрашивает активных пользователей, сессии, просмотры страниц, показатель отказов и среднюю длительность визита через Data API v1beta.
  - Метрики интегрированы в верхний KPI-радар и детальную карточку на странице `/seo`.
- **Синдикационные новостные фиды (XML)**:
  - `/api/feeds/yandex-news.xml` — строгий RSS 2.0 фид со спецификацией Яндекс.Новостей (`<yandex:full-text>`, медиа-вложения `<enclosure>` и `<media:content>`).
  - `/api/feeds/rss.xml` — чистый стандартизированный RSS 2.0 фид для агрегаторов и читалок.
  - *Примечание по Турбо*: Яндекс официально прекратил поддержку технологии Турбо для контентных сайтов в апреле 2025 года и удалил раздел из Вебмастера. Мобильный трафик теперь поступает напрямую на адаптивный сайт `svodka.press`.

## 2. Запланировано (в коде отсутствует)

### 2.1 Подбор ключевых запросов (Фазы 2–3)

Тема новости → Wordstat или аналог → топ-5 запросов. Это отдельный механизм от
аналитики опубликованных материалов.

Ключи не остаются «словами в промте»: автор вшивает их органично в заголовки,
лид, подзаголовки и метаполя. SEO/GEO-QA затем проверяет наличие, плотность,
читабельность и отсутствие переспама. Цель — помогать поиску понять тему,
не ухудшая текст для человека.

### 2.4 Видимость в ответах ИИ

Из `PROJECT.md`: отслеживать результативность в SEO **и ответах ИИ**. Код пока
не содержит ни источника данных, ни метода измерения. Отдельное проектирование:
что считать видимостью, какие запросы тестировать, как получать воспроизводимые
результаты и не путать их с персонализированными ответами моделей.
