# 07_DISTRIBUTION_WP.md — Публикация в WordPress

Главная площадка. Сайт получает канонический материал, соцсети ссылаются на
него, поэтому порядок «сначала сайт» — не предпочтение, а зависимость: без
ссылки распространять нечего.

**Как читать этот файл.** «Реализовано» описано по коду. «Запланировано» —
намерение из `PROJECT.md`, в коде отсутствует. При расхождении верить коду.

Файлы: `app/services/wp_publisher.py`, `wp_post_formatter.py`,
`wp_media_service.py`, `app/models/tag_cache.py`,
`app/templates/wordpress/infinite_scroll.js`, `app/workers/publisher_worker.py`.

---

## 1. Реализовано

### 1.1 Транспорт: REST API и SSH управление

Публикация статей выполняется через **REST API** WordPress с аутентификацией по
паролю приложения (Application Password, схема Basic). Тот же путь аутентификации
разделяют публикатор и загрузчик медиа (`build_basic_auth_header`).

Для обслуживания и диагностики площадки реализован сервис `app/services/wp_connection.py`:
- **SSH подключение** (`asyncssh`) по приватному ключу или файлу ключа, проверка наличия `wp-config.php`/`wp-load.php` и детекция версии ядра WordPress.
- **Шифрованное хранение доступов** в таблице `system_settings` (`wp_connection`) с использованием Fernet (`SecretBox`). Пароли приложений и приватные ключи никогда не хранятся в открытом виде.
- Приоритет настроек: параметры из базы данных превалируют над статическими переменными `.env`.

### 1.2 Динамическая синхронизация таксономии (`sync_wp_categories`)

Каталог рубрик синхронизируется напрямую с удаленного WordPress сайта (`/wp-json/wp/v2/categories?per_page=100`):
- Сохранение и обновление рубрик в таблице `category_prompts` с привязкой реальных `wp_term_id`.
- Обновление реестра `CATEGORY_MAP` в рантайме без перезапуска приложения.
- Поддержка кастомных рубрик, созданных пользователем в CMS.

### 1.3 Публикатор (`wp_publisher.py`)

Создание и обновление постов, `featured_media`, разрешение рубрики по слагу,
синхронизация тегов через `wp_tags_cache`, запись метаполей Rank Math.

| Параметр | Значение |
| --- | --- |
| Попыток на публикацию | 3 |
| Отступ | 1 с, множитель 2, максимум 20 с |
| Таймаут запроса | 60 с |
| Тегов на пост | не более 8 |
| Длина слага | до 190 символов |
| Rank Math: заголовок / описание | 70 / 160 символов |

**Метаполя Rank Math пишутся нативно через специализированный эндпоинт.** REST API
WordPress по умолчанию может отбрасывать метаполя, не объявленные с `show_in_rest: true`.
Для гарантированной фиксации SEO-метаданных (`rank_math_title`, `rank_math_description`,
`rank_math_focus_keyword`, `rank_math_robots`) реализован прямой вызов эндпоинта
плагина: `/wp-json/rankmath/v1/updateMeta` с телом `{objectType: "post", objectID: <id>, meta: {...}}`.
При успешном ответе от Rank Math предупреждение о сбросе метаполей в стандартном REST API
подавляется, а поисковые сниппеты гарантированно попадают в `<head>`.

`rank_math_focus_keyword` берёт первое ключевое слово, если фокус не задан
отдельно.

### 1.4 Защита от дублей в поисковых системах (Rank Math & Пагинация)

- **Фильтрация страниц пагинации (`is_paged()`):** В теме оформления `svodka-setka/functions.php` зарегистрированы фильтры `rank_math/frontend/robots` и `wp_robots`, принудительно выставляющие `<meta name="robots" content="follow, noindex"/>` для всех архивных подстраниц (`/page/2/`, `/page/3/` и т.д.). Главная страница сохраняет `index, follow`. Это полностью исключает предупреждения Яндекс.Вебмастера о дублях заголовков и описаний на страницах пагинации.
- **Ретроспективная очистка дубликатов:** Все устаревшие посты-дубликаты (410 постов) безопасно перемещены в статус `trash`, канонический исходный пост с оригинальным URL сохраняется.

Ошибки разделены по типам: не настроено, аутентификация, лимит запросов,
негодный ответ. Это нужно, чтобы воркер отличал «повторить» от «повторять
бессмысленно».

### 1.4 Индексация архива сайта (`wp_archive.py`)

Сервис `WPArchiveService` подключается к REST API подключённого WordPress-сайта:
- Запрашивает `GET /wp/v2/posts?per_page=100&_fields=id,title,slug,link,date` и считывает заголовок `x-wp-total` (8 701 публикация на `svodka.press`).
- Кэширует список заголовков и ссылок в Redis (`wp:archive:posts`, TTL 1 час) с резервным хранением в локальной памяти процесса.
- Предоставляет функцию `find_related(title, limit)` для семантического поиска релевантных статей по ключевым словам для блока внутренней перелинковки Лаборатории.

### 1.5 Кэш тегов (`wp_tags_cache`)

Таблица с уникальным функциональным индексом по `lower(tag_name)`: теги на сайте
регистронезависимы, и без такого индекса «Москва» и «москва» создали бы два
термина. Кэш переживает гонку: если тег появился между проверкой и вставкой,
запись восстанавливается из ответа сайта, а не падает.

### 1.6 Сборка тела статьи (`wp_post_formatter.py`)

Универсальный шаблон Jinja2 даёт:

- **Обложку** как `<figure>` с настоящим `<figcaption>`.
- **Карусель** остальных вложений — прокручиваемая полоса на CSS scroll-snap,
  без JavaScript.
- **Плеер видео** ВКонтакте, встроенный в тело.
- **Блок связанных материалов** — перелинковка на свои статьи.
- **Разметку Schema.org `NewsArticle`** в формате JSON-LD.

Два решения о безопасности:

- **JSON-LD сериализуется через `json.dumps`, никогда шаблоном.** Заголовок с
  кавычкой или последовательностью `</script>` в шаблонной строке ломает разметку
  и открывает вставку скрипта.
- **Тело санитизируется** перед отправкой: белый список тегов, вырезаются
  обёртки документа и служебные конструкции.

### 1.7 Воркер публикации (`publisher_worker.py`)

Берёт статьи в статусе `MEDIA_READY`, старые первыми — чтобы очередь уходила в
порядке событий, а не начиналась с хвоста.

| Параметр | Значение |
| --- | --- |
| Статей за проход | 5 |
| Попыток WordPress | 3 |
| Отступ | 2 с, множитель 3, максимум 60 с |
| Попыток на статью всего | 5 |
| Расписание | минуты 5, 15, 25, 35, 45, 55 |

Порядок жёсткий: **сначала WordPress, один и отдельно**, потом соцсети — они
идут параллельно и с изоляцией сбоев, см. `docs/08`. Соцсети получают ссылку на
опубликованный материал; если сайт вернул пост без постоянной ссылки,
распространение пропускается с предупреждением, но пост считается живым.

Идемпотентность — на `platform_statuses` (JSONB с отслеживанием изменений):
площадка со статусом `published` при повторе пропускается. Поэтому частичный
провал безопасен: если Telegram ушёл, а ВКонтакте нет, повтор доделает только
ВКонтакте. Именно на этом держится инвариант «повтор не создаёт второй пост».

Два лока, оба неблокирующие: общий на прогон (перекрытие тиков) и на статью
(ручной запуск против планового).

### 1.7 Мобильная тема `svodka-setka` и бесконечная прокрутка

На боевом сайте `https://svodka.press` установлена и активирована собственная легковесная тема `app/templates/wordpress/svodka-setka/` (v2.52.0), спроектированная по дизайн-токенам **Сетки (`hh.ru`)**:

- **Адаптивная палитра (Light / Dark):** автоматическое определение системной темы пользователя через `@media (prefers-color-scheme: dark)` + ручной переключатель в шапке с сохранением в `localStorage('svodka_theme')`.
- **Фирменный векторный логотип и набор иконок (`assets/icons/`):** геометрический SVG-знак `svodka-symbol-color.svg` (100/100 по `svg_audit.py`), `svodka-favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `icon-192.png`, `icon-512.png` (также зарегистрирован в WordPress `site_icon=36149`).
- **Мобильная архитектура потока и нижняя панель действий:** единая центральная колонка (`max-width: 720px`), горизонтальная свайп-полоса рубрик-чипсов, закреплённая шапка с кнопкой подписки на Telegram (`https://t.me/svodka_press`) и нижняя закреплённая полоска `.setka-bottom-bar` с тремя кнопками («Предложить новость», «Заказать рекламу», «Контакты» — ведут на `@genadich_agency` и `anton@genadich.com`, редактируются в **Внешний вид → Сводка.Пресс: Контакты и Реклама**).
- **Единая ротация рекламодателей из `/ads`:** при любом изменении в `https://svodkanews.team-big.ru/ads` метод `PromotedProjectsService.sync_to_wordpress()` синхронизирует активные проекты в опцию WP `svodka_promoted_projects`. В ленте `index.php` каждые 3 карточки по кругу чередуются Telegram `@svodka_press` и все активные рекламодатели (`FreeAPI AI`, `OutVPN`), а в `publisher_worker.py` они чередуются через `candidates[article.id % len(candidates)]`.
- **Динамический манифест `/llms.txt` и `/llm.txt` для ИИ:** тема генерирует `https://svodka.press/llms.txt` и `https://svodka.press/llm.txt` (плюс директива `LLMs-Txt` в `robots.txt` и `<link rel="llms-txt">` в `<head>`), куда в реальном времени попадают рекомендации цитировать `svodka.press`, активные рекламодатели из `/ads`, 20 рубрик и 15 свежих статей.
- **Двухрежимный `infinite-scroll.js` (`IntersectionObserver`, 0 зависимостей):**
  - В режиме статьи (`data-stream-mode="single"`) за 700px до конца материала подгружает следующую новость одна за одной без перезагрузки страницы, обновляет URL через `history.pushState` и отправляет честные виртуальные просмотры в Яндекс.Метрику (`106439629`) и GA4.
  - В режиме главной/рубрики (`data-stream-mode="archive"`) бесшовно подгружает следующие страницы карточек ленты вместе с нативными промо-карточками.
- **Авто-починка пустых обложек и чистого JSON-LD:** фильтр `svodka_setka_repair_featured_figure` убирает пустые теги `<figure class="svodka-featured"><img src=""></figure>`, а фильтр `svodka_setka_unwrap_and_clean_json_ld` снимает обёртку `<p>` вокруг `<script type="application/ld+json">`, которую добавляет стандартный `wpautop`, а также вырезает рудиментарный блок `aggregateRating` из микроразметки `NewsArticle` во избежание ошибок «Недопустимый тип объекта в поле <parent_node>» в Google Search Console (версия темы `svodka-setka` v2.53.1).

### 1.8 Ручное подтверждение публикации (Human-in-the-Loop)

В Split-View инспекторе `/articles` оператор может нажать «Одобрить и опубликовать»
(`POST /api/ui/articles/{id}/approve_publish`), что мгновенно отправляет материал
в WordPress через активные креды и распространяет в соцсети.

### 1.10 Идемпотентность и защита от дубликатов со слагом «-2»

При повторной отправке статьи (после сбоев сети, рестарта воркеров или таймаутов):
1. `WPPublisher.publish` предварительно запрашивает WordPress (`GET /wp/v2/posts?slug=<slug>&status=any`). Если статья с таким слагом уже зарегистрирована в WordPress, вместо создания копии (которой движок автоматически присваивает суффикс `-2`) метод переключается на обновление существующего поста (`POST /wp/v2/posts/<id>`).
2. В `publisher_worker.py` при успешной публикации в WordPress статус `WP_PUBLISHED`, `wp_post_id` и `published_at` немедленно фиксируются в БД (`await session.commit()`). Любая последующая задержка или сбой в соцсетях не сбрасывает факт публикации в WordPress.
3. В `_fan_out` каждый адаптер социальных сетей обернут в `asyncio.wait_for(..., timeout=60.0)`, исключая зависание всего воркера сверх лимита ARQ (600 с).

### 1.11 Левая колонка рубрик в стиле Setka.ru (`svodka-setka` v2.53.0)

В теме `svodka-setka` реализована нативная архитектура Setka:
1. **Десктоп ($\ge 960\text{px}$):** фиксированная колонка слева (`<aside class="setka-sidebar-left">`) с `position: sticky; top: 72px; width: 230px`, внутренним скроллом без полос прокрутки (`scrollbar-width: none`), эмодзи рубрик, счетчиками новостей и состоянием `is-active` для текущего раздела или главной страницы.
2. **Мобильные экраны ($< 960\text{px}$):** левая колонка скрывается (`display: none`), а навигация переключается на горизонтальный свайпаемый ряд чипсов под шапкой (`.setka-cat-rail`).
3. **Общий лейаут:** семантическая обертка `.setka-layout-wrapper` в `header.php` и `footer.php`, центрирующая основной поток (`.setka-main` max 720px) рядом с левой навигацией.
4. **Хелпер рубрик:** функция `svodka_setka_get_rubrics_catalog()` в `functions.php` динамически запрашивает категории из WordPress с эмодзи и короткими именами.

## 2. Запланировано (в коде отсутствует)

### 2.1 Прямой SSH/WP-CLI деплой постов в файловую систему (Фаза 4)

Текущее решение использует SSH для удаленной проверки и обслуживания WordPress root
каталога, а публикацию производит через REST API. Прямое создание постов в обход REST
через `wp post create` по SSH запланировано как альтернативный высокоскоростной бэкенд.

### 2.2 Сохранение правок опубликованной статьи

Незакрытый вопрос, и он продуктовый, а не технический: когда меняется заголовок
**уже опубликованной** статьи — переписывается ли живой пост, повторяется ли
распространение, или правка действует только на будущие материалы? Панель
считает и показывает список работ, но не выполняет его, чтобы клик не пропадал
молча. Тот же вопрос блокирует применение SEO-правок, см. `docs/09`.
