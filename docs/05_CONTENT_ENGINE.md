# 05_CONTENT_ENGINE.md — Контентный движок

Модерация кластера, генерация статьи, проверка качества, anti-slop, рубрики и
маршрутизация моделей.

**Как читать этот файл.** Раздел «Реализовано» описан по коду и подтверждён
тестами. Раздел «Запланировано» — намерение из `PROJECT.md`, в коде его нет.
При расхождении документа с кодом верить коду.

Файлы: `app/services/moderator.py`, `content_generator.py`,
`content_prompts.py`, `content_fixer.py`, `slop_filter.py`, `categories.py`,
`model_routing.py`, `model_pool.py`, `research.py`, `app/workers/content_worker.py`.

---

## 1. Реализовано

### 1.1 Порядок шагов в `content_worker`

Оркестратор — единственное место, где семь сервисов собираются вместе. Сервисы
возвращают значения и никогда не коммитят: границы транзакции, порядок и
политика «что считать провалом» живут в воркере.

1. Взять кластер без статьи (проверка запросом, не флагом).
2. **Модерация** (`moderate_with_fallback`) — рубрика и уровень риска.
   Вердикт `spam` останавливает кластер здесь, до любого платного вызова.
3. **Генерация** (`generate_article`) в стиле рубрики.
4. **Проверка и правка** (`content_fixer`) — с повторным прогоном anti-slop.
5. **Вектор** финального текста (`embedding_service`) в `articles.final_embedding`.
6. **Медиа**: вотермарки → обрезка → при нужде генерация обложки → загрузка в
   WordPress. Подробности — `docs/06_MEDIA_PROCESSING.md`.
7. **Видео** во ВКонтакте, плеер встраивается в тело.
8. Сохранить `Article` в статусе `MEDIA_READY`.

Параметры прохода:

| Параметр | Значение |
| --- | --- |
| Кластеров за проход | 10 |
| Исходных фото на кластер | до 4 |
| Таймаут загрузки медиа | 60 секунд |
| Максимум: фото / видео | 32 МиБ / 256 МиБ |
| Расписание | минуты 2, 12, 22, 32, 42, 52 |

Три решения, которые легко «упростить» до ошибки:

- **Одна транзакция и один лок на кластер.** Пакет из десяти кластеров даёт
  десять коммитов: провал на седьмом не откатывает шесть готовых статей. Лок на
  кластер не даёт ручному запуску из панели столкнуться с плановым и заплатить
  за одну генерацию дважды.
- **Идемпотентность — проверка уникальности, а не флаг.** Кластер со статьёй
  пропускается запросом; `articles.url_slug` несёт уникальный индекс как
  страховку на уровне базы.
- **Провал текста роняет статью, провал медиа — нет.** Без текста публиковать
  нечего, статья помечается `failed`. Без обложки WordPress отрисует пост, и
  терять статью из-за недоступного CDN — неверный обмен.

### 1.2 Модерация (`moderator.py`)

Возвращает JSON: рубрика, уровень риска, причина. Схема ограничена энумом из
20 рубрик, поэтому модель не может придумать свою.

Уровни риска: `green`, `yellow`, `red`, `spam`. `spam` — не степень риска, а
четвёртое состояние: реклама и самопиар отбрасываются до генерации, поэтому ни
статьи, ни расхода не возникает (`RiskLevel.blocks_generation`).

Жёсткие правила продублированы в коде, а не только в промте — модель их
периодически игнорирует: происшествия и военные новости получают свою рубрику
принудительно, при сомнении берётся рубрика по умолчанию. Факт переопределения
записывается (`overridden`, `override_note`) и виден в «Лаборатории».

Любое поле деградирует к безопасному значению вместо исключения: неизвестная
рубрика → `DEFAULT_CATEGORY` (`novosti-obshhestva`), с записью в лог.

### 1.3 Рубрики и стили (`categories.py`, `content_prompts.py`, `lab_pipeline.py`)

20 рубрик, у каждой номер термина WordPress. **Номера зашиты в код** под
`svodka.press` — это подтверждённый дефект тиражируемости, см. раздел 2.

Стилей письма шесть, не двадцать: пять из спецификации покрывают 18 рубрик,
астрология и киберспорт получили шестой. Рубрика отображается в стиль через
`style_for(slug)`, стиль задаёт форму лида, структуру и список запретов.

В интерактивной Студии Лаборатории (`lab_pipeline.py`) реализованы глубокие профессиональные журналистские промты:
- **Информационный** (по умолчанию): фактологический объективный стиль информагентств (ТАСС/РИА Новости), строгая инвертированная пирамида (кто, что, где, когда, почему, с какими последствиями).
- **Аналитический**: деловая пресса уровня «Коммерсантъ» и «Ведомости», причинно-следственные связи, экономический контекст, влияние на рынок/отрасль, баланс сил.
- **Срочная молния**: формат Breaking News, ультра-плотный лид до 150 знаков, хроника событий в реальном времени, фиксация только подтверждённых данных.
- **Лонгрид**: фундаментальный аналитический материал 2500–4000 знаков, контекст события, предыстория, альтернативные мнения, несколько уровней подзаголовков (`<h2>`, `<h3>`), расширенный фактчек.
- **Ироничный обзор**: сатирический интеллектуальный фельетон, язвительная аналитика, едкая ирония без перехода в площадную брань и пошлость.

**Интерактивное переключение в Студии:** выбор стиля в выпадающем списке на Шаге 3 мгновенно подставляет соответствующий развёрнутый промт в текстовое поле редактирования через клиентский скрипт `window.labStylePrompts`, позволяя редактору донастроить нюансы перед генерацией.

Контракт вывода:

| Поле | Ограничение |
| --- | --- |
| `title` | ≤ 70 символов |
| `seo_description` | ≤ 160 символов |
| `seo_keywords` | от 3 до 6, каждое ≤ 128 символов |
| `content_html` | ≥ 900 символов |
| `Тело` | чистый HTML, без обёрток и упоминаний каналов |

### 1.4 Промты в базе (`category_prompts.py`)

Начиная с миграции `0007_category_prompts`, оператор может переопределять промты
рубрик из панели и создавать кастомные рубрики. Таблица `category_prompts` хранит
только отличия от встроенных значений: если строки нет, берётся дефолт из
`content_prompts.CATEGORIES`.

**Разрешение при генерации и модерации.** `PipelineRunner` загружает все строки
через `load_prompt_overrides(session)` и передаёт словарь в:

- `build_system_prompt(category, overrides)` и `build_user_prompt(..., overrides)`
  в `content_prompts.py`;
- `build_moderation_prompt(overrides)` и `moderation_schema(overrides)` в
  `moderator.py` — кастомные рубрики добавляются в enum схемы;
- `generate_article(..., overrides)` и `validate_generation(..., overrides)` в
  `content_generator.py` — кастомные slug'и принимаются как валидные.

**Операции.** `save_prompt_override` (переопределение встроенной),
`create_custom_prompt` (новая рубрика), `delete_prompt_override` (сброс к
дефолту или удаление кастомной). Кастомные рубрики помечаются `is_custom=True`
и появляются в списке модератора наравне со встроенными.

**Почему не кэш.** Переопределения читаются на каждый прогон, а не кэшируются:
оператор правит голос и сразу нажимает «Статья без сбора» — ожидание, что
изменение применится без перезапуска, прямо противоположно кэшу.

### 1.5 Генерация (`content_generator.py`)

Асинхронный вызов через шлюз, проверка по схеме и через anti-slop, **одна**
корректирующая попытка (`MAX_GENERATION_ATTEMPTS = 2`), бюджет 4096 токенов.
`risk_level` доходит до автора: `yellow` смягчает тон, происшествия и военные
получают экстренную форму.

**Лаборатория и расширенный контекст ресерча:**
- **Глубокий контекст внешнего ресерча:** `lab_pipeline.py` агрегирует до 1500 символов
  фактологического текста на каждый проверенный веб-источник и передаёт его под блоком
  `=== КОНТЕКСТ И АНАЛИТИЧЕСКИЕ ДАННЫЕ ИЗ ВНЕШНЕГО РЕСЕРЧА ===`.
- **Anti-boring директива:** в системный промт внедрено обязательное требование
  интегрировать данные бэкграунда и ресерча (цифры, цитаты, хронологию событий),
  запрещая сухие отписки и скучные пересказы телеграм-постов.
- **Инъекция пользовательского стиля:** параметр `custom_style_prompt` пробрасывается
  из интерфейса Студии Лаборатории в `generate_article` и внедряется в конец
  пользовательского сообщения как директива «СТИЛЕВОЙ ФОРМАТ И ДОПОЛНИТЕЛЬНЫЕ ИНСТРУКЦИИ».
- **Внутренняя перелинковка с архивом:** сервис `WPArchiveService` кэширует 8 700+ статей
  с сайта `svodka.press`, находя релевантные прошлые публикации по ключевым сущностям
  и автоматически внедряя контекстные ссылки и блоки «Читайте по теме».

### 1.6 Anti-slop (`slop_filter.py`)

39 правил, разделённых по severity, а не плоским списком:

- **`FATAL`** (29) — черновик отклоняется и переписывается. Это либо чистая
  вода, либо фраза, которая ломает доверие к тексту.
- **`SOFT`** (10) — правится на месте через `clean_ai_slop`, без повторного
  вызова модели.

Счётчики берутся из кода (`FATAL_PATTERN_COUNT`, `SOFT_PATTERN_COUNT`), а не
записаны руками, поэтому не разойдутся при правке списка.

Есть плотность попаданий на 1000 слов. Один `FATAL` обнуляет черновик целиком.
Проверка идёт **до** записи в базу — это инвариант проекта.

### 1.7 Проверка и правка (`content_fixer.py`)

Бесплатная часть: верность фактам, структура, лимиты метаполей, связность
(скан первых 4000 символов), остаточный slop. Платная часть — точечная правка
через модель, бюджет 4096 токенов.

Ключевой порог: `MAX_DROPPED_FACT_RATIO = 0.34`. Если автор потерял больше
трети фактов исходника, текст считается негодным — это защита от пересказа,
который звучит гладко и не сообщает того, что было в источнике.

### 1.8 Маршрутизация и пул моделей (`model_routing.py`, `model_pool.py`)

`model_routing.py`: модель на каждую роль (`arbiter`, `writer`, `seo`,
`embedding`, `image`) в `system_settings`, `.env` — только резерв. Правится из панели,
применяется без перезапуска. Цепочка на роль — 3 модели.

`model_pool.py`: `run_with_fallback` идёт основная → резерв 1 → резерв 2.

- Временный сбой (429, 5xx, транспорт, негодный ответ) — переход к следующей.
- Ошибка конфигурации (400/401/403/404) **не** повторяется: она одинакова на
  всех моделях, и перебор цепочки закопал бы настоящую причину.
- Кулдаун 60 секунд, плоский, в Redis. Плоский намеренно: растущий штраф
  перегнал бы все стадии на худшую модель. В Redis, а не в процессе — три
  воркера и веб не должны каждый заново открывать, что модель мертва.
- Кулдаун на роль: модель, живая для короткой классификации, может падать на
  длинной статье.
- Полностью остывшая цепочка всё равно пробует основную: остановленный конвейер
  хуже одного лишнего вызова.

### 1.8.1 Мульти-провайдерный роутинг и каталог моделей (`ai_client.py`, `gemini_key_pool.py`)

1. **Прямая маршрутизация по провайдерам (`_dispatch_provider_call`):**
   - Вызовы моделей `gemini-*` и `gemma-*` направляются напрямую в Google AI Studio (`generativelanguage.googleapis.com`) через пул активных ключей с ротацией Round-Robin и отслеживанием кулдаунов 429.
   - Вызовы кастомных моделей (`vsllm.cc`, `api.apinex.bond`) направляются напрямую к соответствующему `/v1/chat/completions` эндпоинту с соответствующим Bearer-токеном.
   - Внешний шлюз OpenRouter используется как резервный транспорт, если модель не сопоставлена ни с одним активным пулом ключей в БД.

2. **Проверка работоспособности моделей (`AIProviderModel`):**
   - Каждая обнаруженная модель хранит статус `is_working`, дату последнего теста `last_tested_at` и читаемый текст ошибки `error_message` (очищенный от HTML-тегов Cloudflare и JSON-обёрток).
   - В UI доступны:
     - Поштучный тест любой модели (`⚡ Тест`) с изолированным обновлением строки (без скачков скролла).
     - Пакетный тест топ-5 моделей пула (`🧪 Топ-5`).
     - **Массовый параллельный тест 100% моделей провайдера (`⚡ Тест 100%`):** параллельный опрос с семафором `asyncio.Semaphore(6)` для проверки всех обнаруженных моделей (сотни моделей шлюзов `dollariuy.fun`, `vsllm.cc` и др.) без превышения Rate Limit.
     - **Глобальное тестирование всех моделей во всех пулах:** одновременный запуск проверки всей инфраструктуры в один клик.
   - Функция `auto_recover_unhealthy_models()` автоматически перепроверяет модели, временно упавшие из-за транзитных сетевых или 429/502/503 ошибок.

3. **Каталог проверенных моделей (`get_working_models_catalog`):**
   - Собирает только подтверждённые рабочие модели (`is_working=True`) от активных ключей (`is_active=True`).
   - Группирует модели по провайдерам, исключает дубликаты, разделяет на генеративные (`chat_options`), векторные (`embed_options`) и модели генерации изображений (`image_options`).
   - На проде после 100% тестирования доступно 43 уникальные проверенные модели (включая Claude Sonnet 4.6/5, Claude Opus, Grok 4.5/4.6, DeepSeek Flash/Pro, GPT-5.5/5.6 и Gemini).

4. **Умная матрица назначения и автоподбор (`auto_select_best_models`):**
   - Поля назначения моделей в `/settings/ai` используют выпадающие списки `<select>` с фильтрацией по проверенным моделям для всех 5 ролей: Арбитр, Генератор текста, SEO, Эмбеддинги, Генератор обложек.
   - Кнопка «✨ Автоподбор лучших моделей» в один клик определяет оптимальные модели для 5 ролей с приоритетом быстрых недорогих моделей для арбитра, флагманских для автора, 0-токеновых FastEmbed для эмбеддингов и Fal AI Flux Schnell для обложек.


### 1.9 Ресерч (`research.py`, `web_researcher.py`, `web_search.py`)

Модуль ресерча объединяет локальный и внешний контекст для обогащения статей:

1. **Внешний веб-ресерч (`web_researcher.py`, `web_search.py`):**
   - Автоматическое формирование поискового запроса (`extract_search_query`): выделение первого смыслового предложения через регулярное выражение границ предложений `(?<=[.!?])\s+(?=[А-ЯA-Z0-9«\"])|\n+`, что полностью предотвращает ложное разбиение на точках внутри сущностей (`Z.ai`, `GLM-5.3`, `domain.ru`).
   - Очистка от лидирующих эмодзи, мусорных префиксов («Срочно», «Молния»), с сохранением естественных предлогов и грамматической связности для поисковых систем (до 8 ключевых слов).
   - Поиск релевантных источников через DuckDuckGo HTML parser с разворачиванием редиректов (`uddg`).
   - Фильтрация социальных сетей (Telegram, VK, OK, Twitter, Facebook).
   - **Строгая SSRF-защита (`is_safe_web_url`, `_is_safe_hostname`):** блокировка приватных сетей (RFC 1918), loopback (`127.0.0.0/8`), link-local (`169.254.0.0/16`), cloud metadata (`169.254.169.254`), небезопасных портов и схем, отличных от HTTP/HTTPS.
   - Извлечение чистого текста статей через Trafilatura с лимитом размера 1 МБ и таймаутом 6 с.
   - Эвристическое извлечение ключевых фактов (даты, числовые метрики, цитаты) без затрат токенов LLM (`_extract_key_facts`).
   - **Семантический анализ релевантности и отсечение оффтопика (`evaluate_article_relevance`, `_stem`):**
     - Встроенный легковесный стеммер (`_stem`) для нормализации окончаний русского и английского языков без внешних тяжелых зависимостей (устраняет расхождения между словоформами «модель», «модели», «китайская», «китайский»).
     - Выделение именованных сущностей и терминов (`_extract_entities_and_terms`): фиксация моделей и марок с точками (`GLM-5.3`, `Z.ai`), капитализированных имен, числовых показателей и ключевых существительных темы.
     - Композитный расчет релевантности: совпадение ключевых сущностей (вес 50%), пересечение стеммированных ключевых слов (вес 30%) и лексическое совпадение заголовка (вес 20%).
     - Строгий порог отсечения: кандидаты с баллом ниже 0.30 или с нулевым совпадением ключевых сущностей темы отклоняются (например, случайные статьи об автопроме при ресерче новости об ИИ).
     - Сверхвыборка кандидатов (`max_sources * 2`): сбор до 6 ссылок из поисковой выдачи с последующей фильтрацией для гарантированного сохранения 3 релевантных источников.
     - Индикация релевантности в интерфейсе Студии Лаборатории (бейджи `✓ В тему (XX%)` или `⚠️ Контекст (XX%)`).
   - Аугментация промта генератора статьи контекстным блоком `=== КОНТЕКСТ И ПРЕДЫСТОРИЯ СОБЫТИЯ ИЗ СЕТИ ===`, позволяющим расширить материал до целевых 2000–4000 знаков.

2. **Локальный контекст, форматирование фактов и перелинковка (`research.py`):**
   - `collect_facts` агрегирует факты из Telegram-постов кластера и нормализует сырые токены MinHash (`ent:`, `when:`, `date:`, `money:`, `num:`, `pct:`) в читаемые формулировки через `format_fact_label` («Ключевой объект: ...», «Сумма: ...», «Показатель: ...»).
   - При отсутствии развернутой фактуры автоматически подтягивает ключевые вводные предложения из первоисточников.
   - `find_related_articles` ищет похожие свои опубликованные материалы за 30 дней для внутренней перелинковки (до 3 ссылок).
   - Единая точка оркестрации: `conduct_cluster_research(...)` объединяет локальные факты, веб-источники и перелинковку.

### 1.10 Подбор поисковых запросов и Wordstat (`wordstat_collector.py`)

Сервис сбора поисковых фраз и частотности для SEO-оптимизации статей:

- **Интеграция с официальным Yandex Wordstat API**:
  - Прямой эндпоинт `api.wordstat.yandex.net/v1/topRequests` (OAuth-токен) или Yandex Cloud Search API `searchapi.api.cloud.yandex.net/v2/wordstat/topRequests` (API-ключ + Folder ID).
  - Строгая защита квоты: максимум 95 запросов в час со скользящим окном в Redis.
  - Кэширование ответов Wordstat в Redis на 24 часа (`wordstat:v1:{query}`).
- **Семантический ИИ-фоллбек**:
  - При отсутствии API-ключей Яндекса или исчерпании лимита запускается нейросетевой подбор реальных поисковых фраз с расчётом правдоподобной частотности для русскоязычного сегмента и классификацией интента (`информационный`, `навигационный`, `коммерческий`).
  - Генерация файла `llm.txt` для поисковых AI-агентов.

### 1.11 Стандарты блога Excalibur и микроразметка Schema.org (`schema_org.py`)

Реализация стандартов качества контента по спецификации Excalibur:

- **Органичное внедрение фокусного ключа**:
  - Ключевой запрос внедряется в `title`, первые 150 знаков лида и один из подзаголовков `<h2>` без переспама.
- **Оценка лид-хука (Lead Hook Score)**:
  - Проверка первого абзаца: оптимальная длина 300–500 знаков, наличие конкретных фактов и цифр, отсутствие журналистских штампов и клише (блоклист `ai-slop`).
- **Микроразметка Schema.org JSON-LD**:
  - Формирование валидного JSON-LD для графа `NewsArticle` (с автором, издателем, датой и `mainEntityOfPage`).
  - Формирование блока `FAQPage` с извлечением вопросов и ответов из структуры статьи.

### 1.12 Алгоритмический индекс привлекательности (AEVI) и мультиканальный Split-View в Студии Лаборатории (`aevi_scoring.py`, `lab_pipeline.py`)

Начиная с версии `2.30.0`, в Лаборатории реализована автономная система отбора и приоритизации самых интересных новостей:

- **AEVI (Audience Engagement & Virality Index 0–100)**:
  Детерминированный расчет привлекательности на основе 4 векторов реальных данных (0 токенов):
  1. *Поисковый спрос (0–30)*: семантические маркеры неотложного читательского интереса («закон», «выплаты», «указ», «тарифы», «цб», «налог», «штраф»).
  2. *Историческое удержание рубрики (0–30)*: реальная глубина визитов и среднее время на странице (140+ сек = 22 б.) из таблицы `AudienceCategoryMetric` с учётом доли аудитории и штрафа за высокий отказ (>35%).
  3. *Аффинитивность Яндекс.Крипты (0–25)*: пересечение сущностей сюжета с ядром платежеспособных коммерческих интересов читателей (`finance`, `property`, `business`, `auto`, `tech`, `health`, `family`).
  4. *Фактура первоисточников (0–15)*: охват каналов сюжета, наличие точных цифр, прямых цитат спикеров и хронометража.
- **Автоматическая сортировка очереди сюжетов**:
  Сюжеты в Лаборатории ранжируются по `(aevi_score, source_count, posts_count)` убыванию — топовые виральные инфоповоды всегда находятся сверху.
  В интерфейс добавлен быстрый фильтр `🔥 Топ-интерес (AEVI ≥ 55)`.
- **Карточка гипотезы ИИ и замкнутый контур (Closed-Loop Feedback)**:
  До публикации формируется запись гипотезы `HypothesisRecord`: прогноз охвата визитов, времени чтения, целевого портрета ЦА по Крипте и ожидаемого CTR рекламы.
  После выхода статьи на сайт и в соцсети фактические метрики Яндекс.Метрики автоматически сопоставляются с гипотезой для фиксации паттернов-победителей.
- **Мультиканальный 4-Tab Split-View Live Preview**:
  1. 🌐 *Сайт WordPress*: каноническая версия с рекламными блоками РСЯ (Top Billboard 728×90, In-Article 300×250) и внутренней перелинковкой.
  2. 📱 *Яндекс Дзен*: адаптация под Студию Дзена через Playwright Stealth с нативным промо-баннером/врезкой, изолированной от основного сайта.
  3. 💬 *Telegram*: точная имитация UI-карточки поста с обложкой, форматированным текстом, хэштегами и интерактивной кнопкой перехода.
  4. 👥 *ВКонтакте*: вид поста стены сообщества со сниппетом ссылки, обложкой и счетчиками вовлечения.

### 1.10 Редакционный стандарт «ДНК Победителей» (v2.31.0)

На основе анализа 51 000+ сессий читателей и лидеров удержания (статьи с глубиной чтения >75с и отказами <25%):
- **Формула заголовка**: `Субъект/Бренд + Конкретное действие/поворот + Интрига/выгода + 1-2 эмодзи` (например: 🍔❤️, 🤖⚡, 🚇👑, 🍫❤️, 📈🔥). Длина строго до 75 знаков, без кавычек вокруг всего заголовка.
- **Лид (первый абзац)**: строго 2–3 емких предложения (150–250 знаков). Сразу факты: Кто, Что сделал, Где и Почему это важно прямо сейчас.
- **Zero Hallucination (строгий запрет выдумывания)**: запрет генерации вымышленных фактов, дат, имен и цифр. Обогащение строится исключительно на переданных первоисточниках и данных внешнего веб-ресерча (`conduct_cluster_research`).
- **Структура и объем**: 1800–2500 символов HTML, минимум 2 осмысленных подзаголовка `<h2>`, 1 маркированный список `<ul><li>`, живой язык без штампов и канцелярита.

### 1.11 Модуль рекламируемых проектов и нативные статьи о продукте (Brand Journalism)

Вместо баннеров-растяжек (даваших до 99.4% отказов), монетизация строится по модели победного кейса *«Магнит Доставка + Илья Куруч»* (486.7 Quality Engagement Score):
- Модель `PromotedProject` (`app/models/promoted_project.py`): название бренда, продукта, решаемая проблема ЦА, сегменты аудитории, УТП, UTM-параметры и цели конверсий.
- Сервис `PromotedProjectsService` (`app/services/promoted_projects_service.py`): реестр в `SystemSetting('promoted_projects_registry')` с шифрованием Fernet токенов Яндекс.Метрики заказчика.
- Генератор `build_native_advertorial_prompt`: статья пишется как полноценная технологическая или потребительская новость, где продукт решает реальную проблему аудитории, с бесшовным встраиванием размеченной UTM-ссылки.

### 1.12 Строгий фильтр безопасности бренда (Brand Safety Filter)

- **100% запрет коммерческих интеграций**:
  1. Некоммерческие категории: `voennye-novosti`, `chp-i-proisshestvij`.
  2. Стоп-маркеры в заголовке и тексте: `погиб`, `погибли`, `жертвы`, `теракт`, `террорист`, `атака бпла`, `атака дронов`, `дрон`, `бпла`, `обстрел`, `катастрофа`, `крушение`, `взрыв`, `ракета`, `трагедия`, `траур`.
- При срабатывании фильтра нативная реклама блокируется на уровне движка (`is_brand_safe_for_commercial_integration`), а статья генерируется строго по чистому редакционному стандарту.

### 1.13 Сквозной Closed-Loop Feedback и индекс качества кампании (CQI, 0–100)

Комплексная оценка качества интеграции по 4 сбалансированным векторам (`app/services/aevi_scoring.py`):
$$\text{CQI} = \text{BrandSafe} \times (0.25 \times Q_{\text{read}} + 0.25 \times Q_{\text{bounce}} + 0.25 \times Q_{\text{ctr}} + 0.25 \times Q_{\text{target}})$$
- $Q_{\text{read}}$: глубина чтения на медиа (бенчмарк 75с = 80 баллов, 95с+ = 100 баллов).
- $Q_{\text{bounce}}$: фактор отказов на медиа ($(1 - \text{bounce\_rate}) \times 100$).
- $Q_{\text{ctr}}$: нативный CTR ссылки (бенчмарк 4.0% = 80 баллов).
- $Q_{\text{target}}$: конверсии и поведение на сайте заказчика (Метрика клиента через `fetch_client_metrika_stats` по UTM-метке).
- Градации: `🌟 Топ-эффективность (CQI ≥ 75)`, `📈 Хороший результат (55–74)`, `⚠️ Требует калибровки (35–54)`, `❌ Низкая эффективность (<35)`.

### 1.10 Тематическая перелинковка, транслитерация и мульти-фото ресерч (v2.34.0)

- **Тематические кластеры рубрик (`CATEGORY_CLUSTERS`, `_get_category_affinity`)**:
  - `politics_military`: `novosti-politiki`, `voennye-novosti`, `mirovye-novosti`, `novosti-obshhestva`, `zakon-i-pravo`, `chp-i-proisshestvij`.
  - `economy_business`: `ekonomika-i-biznes`, `finansy-i-investicii`, `nedvizhimost`, `kriptovalyuta`, `karera-i-rabota`, `novosti-politiki`.
  - `tech_science`: `it-i-tehnologii`, `nauka-i-kosmos`, `gadgety`, `kriptovalyuta`, `avto-i-transport`.
  - `lifestyle_culture`: `kultura-i-iskusstvo`, `shou-biznes`, `puteshestviya-i-turizm`, `stil-i-moda`, `sport`, `zdorove-i-medicina`, `novosti-obshhestva`.
- **Защита от нерелевантной перелинковки**:
  - Кандидаты для перелинковки отбираются исключительно из аффинитивного кластера рубрик.
  - Поиск совпадений использует морфологический стемминг (`_stem_ru`), устраняя несовпадения из-за склонений («кинотеатры» ↔ «кинотеатрах»).
  - Блок рекомендованного чтения («Читайте по теме: ...») внедряется **только** при наличии реального смыслового пересечения (минимум 1 общий стем). При отсутствии релевантных материалов в базе блок не выводится, исключая абсурдные связки.
- **Канонические URL и транслитерация (`slugify`)**:
  - Внутренние ссылки и канонические адреса статей всегда формируются как абсолютные URL с указанием домена и рубрики: `https://svodka.press/{category}/{slug}/`.
  - Генерация slug использует латинскую транслитерацию `slugify(seo_title, max_chars=180)`: полностью исключены русские буквы, пробелы и замыкающие точки в URL.
- **Обогащение промтов рубрик**:
  - При обнаружении 4-словных заглушек из WordPress («Информационный стиль, сдержанный тон.») система автоматически обогащает промпт развернутым стандартом информагентств `STYLE_PROMPTS['Информационный']` и спецификой рубрики (`lead`, `avoid`).
- **Мульти-фото извлечение ресерча СМИ (`web_researcher.py`)**:
  - Сбор до 6 качественных репортажных фото из внешних новостей с поддержкой `og:image`, `twitter:image`, `srcset`, тегов `<figure>`, `<main>`, `<picture>` и `data-src`/`data-lazy-src`.

## 2. Запланировано (в коде отсутствует)

Из `PROJECT.md`, разделы 4 и 8. Порядок — по фазам плана.

### 2.1 Автономный глубокий ресерч по расписанию для воркера (Фаза 3)

Внешний веб-ресерч уже полностью реализован в интерактивной «Лаборатории» (`web_researcher.py`).
Для фонового конвейера (`content_worker`) запланировано:
1. Автоматический запуск веб-ресерча для приоритетных сюжетов (с флагом глубины).
2. Кэширование результатов поиска в Redis для предотвращения повторных внешних запросов при ретраях генерации.

### 2.2 Промты и рубрики из базы (Фаза 1)

- Промты рубрик уезжают из кода в базу, правятся из панели, применяются без
  перезапуска.
- 20 рубрик и их номера читаются с подключённого сайта. Сейчас зашиты в код —
  на другой установке сайт другой и номера другие.
- Новая рубрика: если новость не подходит ни к одной, система предлагает
  создать (решение владельца от 2026-09-03).

### 2.4 Объём материала (Фаза 3)

Сейчас средняя статья — 1225 символов при минимуме 900. Цель — «максимально
полный и развёрнутый» материал; в n8n заказывалось 2000–4000 символов со
структурой лид → детали → контекст. Правка промтов и порога.

### 2.5 Ручной режим (Фаза 2, приоритет)

Каждый шаг останавливается на одобрение: видны промт, что нашёл ресерч, что
решила модерация, готовый текст. Владелец правит промт и переписывает статью,
пока результат не устроит. Сейчас статья пишется одним проходом без остановок;
«Лаборатория» показывает шаги, но не даёт их подтверждать.

### 2.6 Журнал прогона на каждую статью (Фаза 0)

Файл состояния: какой промт, что нашёл ресерч, где сбой, как обошли. Основа
есть — `ArtifactStore` пишет `storage/runs/<run_id>/`, см. `docs/01`. Нужна
привязка к статье и кнопка в панели.
