# 06_MEDIA_PROCESSING.md — Обработка медиа

Детекция водяных знаков, обрезка, генерация обложек, видео и загрузка в
медиатеку сайта.

**Как читать этот файл.** «Реализовано» описано по коду. «Запланировано» —
намерение из `PROJECT.md`, в коде отсутствует. При расхождении верить коду.

Файлы: `app/services/watermark_detector.py`, `flux_generator.py`,
`vk_video_service.py`, `wp_media_service.py`, медиа-часть
`app/workers/content_worker.py`.

## 1. Реализовано

### 1.1 Общий принцип: медиа не роняет статью

Каждый медиа-шаг возвращает `None` или пустой список при сбое и пишет
предупреждение в отчёт статьи. WordPress отрисует пост без обложки, поэтому
терять готовый текст из-за недоступного CDN — неверный обмен. Провал текста
статью роняет, провал медиа — нет.

Предупреждения складываются в `Article.error_message` (обрезка до 2000 символов),
то есть у статьи в статусе «готово» может стоять пометка «обложку сделать не
удалось».

### 1.2 Детектор водяных знаков (`watermark_detector.py`)

Работает локально и бесплатно: OpenCV + Tesseract, без сети.

**Сканируются семь зон**: четыре угла (`top_left`, `top_right`, `bottom_left`, `bottom_right`), верхняя и нижняя полосы (`top_center`, `bottom_center`) и центральная зона (`center`), чтобы отлавливать как периферийные водяные знаки, так и крупные центральные сплэш-логотипы каналов (ТАСС, 112, РИА Новости, Baza, Mash, SHOT, f-news).

| Параметр | Значение | Смысл |
| --- | --- | --- |
| `MAX_CLEAN_COVERAGE_RATIO` | 0.15 | выше — изображение не «чистое» |
| `CORNER_ZONE_RATIO` | 0.28 | доля стороны на угловую зону |
| `BOTTOM_STRIP_HEIGHT_RATIO` | 0.16 | высота нижней плашки |
| `BOTTOM_STRIP_WIDTH_RATIO` | 0.72 | ширина нижней плашки |
| `MIN_ANALYSABLE_EDGE` | 64 px | меньше — анализ невозможен |
| `MAX_ANALYSIS_EDGE` | 1600 px | крупнее уменьшается перед разбором |
| `MIN_OVERLAY_EDGE_DENSITY` | 0.012 | порог плотности контуров наложения |
| `MIN_BIMODAL_RATIO` | 0.10 | порог двухтональности маски |

**Три независимых метода контроля качества (`watermark_detector.py` + `image_cleaner.py`):**
1. **OCR и брендинг каналов:** Tesseract распознает текст в каждой зоне и сверяет его с доменами, хэндлами (`@channel`, `t.me/`) и списком новостных агентств/каналов (`112`, `ТАСС`, `РИА Новости`, `Baza`, `Mash`, `SHOT`, `Readovka`, `Лента`, `f-news`).
2. **Детектор сплэш-плашек и текстовых карточек (`_detect_monochrome_splash_banner`, `_detect_text_heavy_card`):** отсекает монохромные плашки (сплошной синий фон ТАСС, белый фон «112», черные заглушки), шеринг-карточки OpenGraph (`/sharing/`, `og_image`), квадратные векторные иконки/фавиконки и карточки со сплошным текстом ($\ge 12$ слов).
3. **Маска наложения:** плотность контуров и двухтональность для выявления графических логотипов без читаемого текста.

**Исходы проверки изображения:**
- **Безусловная выбраковка (независимо от `allow_watermarked_source_media`):** сплэш-баннеры каналов, текстовые карточки соцсетей, логотипы в центре кадра и квадратные иконки отбрасываются всегда, вызывая автоматическую генерацию чистой фотореалистичной обложки (`_generate_cover`).
- **Чистое:** без водяных знаков и плашек — публикуется как `source`.
- **Обрезаемое (`cropped`):** водяной знак расположен в верхней или нижней полосе и безопасно срезается без потери композиции.
- **Незначительный водяной знак при `allow_watermarked_source_media = True`:** если это реальная репортажная фотография события (не баннер и не логотип канала), фото сохраняется.

### 1.3 Генерация обложек и резервный фотоархив (`app/services/image_generator.py`)

Унифицированный сервис генерации обложек поддерживает цепочку провайдеров в зависимости от активной роли `image` в маршрутизации моделей (`ai_model_routing`):

1. **Google AI Studio Imagen 3 / Gemini Native Image** (`gemini-3.1-flash-image`, `google/imagen-3.0-generate-002`): прямой вызов REST API с ротацией пула ключей. При возврате HTTP 429 автоматически переключается на резервные генераторы.
2. **OpenAI / Custom Gateways DALL-E 3** (`dall-e-3`): вызов `/v1/images/generations` через подключённые OpenAI-совместимые шлюзы с декодированием Base64 или загрузкой по URL.
3. **Fal AI Flux** (`fal-ai/flux/schnell`, `fal-ai/flux/dev` via `flux_generator.py`): генерация через Fal AI с опросом очереди при наличии ключа `FAL_KEY`.
4. **Pollinations FLUX + Архив репортажных фото СМИ (`pollinations`)**: бесплатная генерация через Pollinations FLUX со случайным `seed`, а при лимите IP (HTTP 402) — автоматический подбор реальной тематической репортажной фотографии через JSON-поиск новостного архива Lenta.ru (`_fetch_news_photo_fallback`).
5. **Отключено (`disabled`)**: возврат `None` (используются исключительно оригинальные медиа из Telegram и веб-ресёрча).

Промт сочиняется на шаге генерации статьи (`image_prompt`, с резервным использованием `title`), соотношение сторон — 16:9 / 1792×1024.

### 1.4 Видео (`vk_video_service.py` и `dashboard.py`)

ВКонтакте используется как видеохостинг: `video.save`, многочастная загрузка,
затем адаптивный `iframe` с плеером `https://vk.com/video_ext.php` встраивается
в тело статьи после первого абзаца. Загружается только первое видео кластера.

- **Автоматический конвейер**: при наличии прямой `http`/`https` ссылки файл скачивается и загружается в VK автоматически.
- **Загрузка из Telegram по требованию (On-Demand из Лаборатории, v2.35.0)**:
  - На карточке видео в Шаге 2 Студии доступна кнопка «⬆️ Загрузить в VK Video» (`POST /api/ui/lab/cluster/{cluster_id}/video/{post_id}/upload-to-vk`).
  - Метод `MTProtoIngestor.download_video()` через Telethon безопасно скачивает `.mp4` файл из канала первоисточника (с лимитом до 500 МБ для защиты RAM контейнера).
  - Сервис `upload_article_video()` резервирует слот в VK API и загружает файл без публикации на стене группы.
  - Метаданные (`vk_owner_id`, `vk_video_id`, `vk_embed_url`) записываются в `raw_news.media_data` и `article.video_links`, а на карточке мгновенно рендерится работающий плеер.

### 1.5 Медиатека сайта (`wp_media_service.py`)

Загрузка через REST: транслитерация кириллического имени файла в слаг, alt,
title и подпись берутся из SEO-полей статьи. Возвращает `media_id`,
`source_url` и `thumbnail_url`; `get_media_url` разрешает `wp_image_id` в
ссылку, чтобы у постов в соцсетях была обложка.

### 1.7 Эндпоинт отложенной доставки и кэширования фото Telegram (`/api/ui/lab/media/photo/{post_id}`)

- **Локальный файловый кэш**: сохранение в `/app/storage/media/telegram/{post_id}.jpg` с заголовками HTTP `Cache-Control: public, max-age=86400`.
- **Загрузка по требованию (On-Demand)**: при отсутствии на диске фото скачивается через `MTProtoIngestor.download_photo()` напрямую из Telegram-канала по `post.source` и `message_id`.
- **Защита от битых иконок браузера**: при временной недоступности сессии Telegram или отсутствии фото возвращается аккуратная векторная заглушка `image/svg+xml` в стиле macOS/Apple с иконкой фотоаппарата и пояснением.

### 1.8 Извлечение и классификация репортажных медиа из веб-источников (`web_researcher.py`)

- **Парсинг микроразметки СМИ**: извлечение тегов `og:image`, `twitter:image`, `link[rel=image_src]` и контентных тегов `<img>` через `lxml.html` при обходе внешних статей.
- **SSRF-валидация**: строгая проверка `is_safe_web_url()` (разрешение IPv4/IPv6, блокировка приватных диапазонов, loopback и спецсетей).
- **Эвристическая классификация медиа (`classify_web_image`)**:
  - Распознавание типа изображения по URL, пропорциям, классам и alt-тексту: `photo` (фоторепортаж), `infographic` (таблицы бенчмарков, диаграммы, графики), `logo` (логотипы брендов, аватары), `graphic` (баннеры, плашки).
  - Первичная фильтрация: при извлечении из статьи кандидаты с логотипами и схемами отсеиваются в пользу реальных репортажных фотографий.
- **Витрина и управление медиа в Студии Лаборатории (Шаг 2)**:
  - Бейджи классификации на карточках картинок (`📸 Фото`, `📊 Таблица/График`, `🏷 Логотип`) с указанием первоисточника.
  - Ручной выбор обложки (`⭐ На обложку`): выбранное изображение подсвечивается изумрудной рамкой, сохраняется в `cluster.enrichment_data["selected_cover_url"]` и при публикации загружается в медиатеку WordPress как главное изображение (`featured_media`).
  - Кнопка скрытия (`✕ Скрыть`): позволяет редактору в один клик убрать неподходящее изображение из галереи.

### 1.9 Редакционные фотожурналистские промты обложек (`lab_pipeline.py`)

- **Стиль репортажной фотожурналистики**: промт для Flux/Imagen формулируется на английском языке в стиле 35mm documentary photography (Reuters/AP).
- **Очистка от визуального мусора**: фильтрация эмодзи (`⚡`, `🔥`), глаголов речи («заявил», «сообщил», «встретился») и клише; формулирование физической сцены и окружения без текста, логотипов и надписей.
- **Интерактивная регенерация**: кнопка «🪄 Перегенерировать промт ИИ» в веб-интерфейсе через HTMX (`POST /api/ui/lab/cluster/{cluster_id}/regenerate-prompt`).

### 1.10 Серверный прокси веб-изображений СМИ (`/api/ui/lab/media/web-image`)

- **Обход anti-hotlink защиты (HTTP 403 Forbidden)**: ведущие новостные порталы (Коммерсантъ, РИА, РБК) блокируют прямое отображение изображений на сторонних сайтах при наличии заголовка `Referer`.
- **Архитектура проксирования**:
  - Валидация URL через `is_safe_web_url()` (защита от SSRF, приватных IP-адресов и внутренних портов).
  - Запрос к оригинальному CDN с маскировкой под браузер и полным исключением заголовка `Referer`.
  - Дисковое кэширование по хэшу SHA-256 в `/app/storage/media/web_cache/{hash}.img` с заголовком HTTP `Cache-Control: public, max-age=86400` (снижение нагрузки на сторонние серверы).
  - Клиентский атрибут `referrerpolicy="no-referrer"` на тегах `<img>`.
  - Векторный фоллбек `image/svg+xml` при сбое сети или тайм-ауте CDN.

### 1.11 Прозрачная диагностика генерации обложек (`lab_pipeline.py`)

- **Устранение тихих сбоев**: исключены фиктивные внешние заглушки (Picsum), которые создавали видимость генерации при отсутствии связи.
- **Явный возврат ошибок (`generation_error`)**: если роль `image` отключена в матрице (`disabled`), провайдер не сконфигурирован или вернул 429 Quota Exceeded, ошибка явно передаётся в контекст шаблона.
- **Интерактивный статус в UI**: в карточке Шага 2 Студии отображается предупреждающий блок с текстом ошибки и прямой кнопкой перехода в `/settings/ai` для включения генератора обложек.
- **Корректный вызов AIClient**: исправление передачи системной инструкции в `generate_editorial_image_prompt` (`system=...`), исключающее сбои при обращении к провайдерам.

### 1.12 Очистка и распределение веб-изображений в статье (`app/services/image_cleaner.py`, v2.36.0)

Новый модуль, реализующий двухэтапный конвейер: сначала чистит собранные веб-фотографии
от дублей и мусора, затем встраивает их в HTML-тело статьи тремя разными способами.

#### Этап 1 — `filter_and_deduplicate_web_images(images, cache_dir)`

Принимает список `dict` с полями `url`, `alt`, `source_domain` из `web_researcher.py`.
Возвращает отфильтрованный список с дополнительным ключом `clean_verdict`.

| Шаг | Метод | Логика |
| --- | --- | --- |
| URL-санитизация | `_filter_url_candidates` | Блэк-лист суффиксов (`.svg`, `.gif`, pixel-трекеры), нормализация query-string, дедупликация по нормализованному URL |
| Скачивание байт | `_fetch_image_bytes` | `httpx.AsyncClient` с дисковым кэшем в `cache_dir` (`storage/media/web_cache/`) |
| Перцептивный хэш | `compute_dhash` | 9×8 grayscale → 64-битный difference hash; `hamming_distance ≤ 8` → дубль, отбрасывается |
| Качество | `inspect_image_quality` | Разрешение ≥ 350×200, соотношение сторон 0.45–2.7, `is_blurry_or_solid` (Laplacian var < 35 или std < 12), `watermark_detector.analyse(coverage > 0.15)` |
| Вердикт | строка | `"Clean photo"` — прошло; `"Duplicate (dHash)"`, `"Too small"`, `"Watermark detected"`, `"Blurry or solid"` — отброшено |

Функция асинхронная, идемпотентная. При `OSError` (read-only файловая система в тестах)
автоматически переключается на временный `Path("storage/media/web_cache")`.

#### Этап 2 — `inject_article_images(html, images, layout)`

Встраивает чистые изображения в HTML-тело статьи. Параметр `layout`:

| Значение | Поведение |
| --- | --- |
| `"inline"` | Вставка `<figure class="article-image svodka-inline-image">` после абзацев 2, 4, 6 (количество зависит от длины статьи). Reverse-sorted вставка сохраняет корректность индексов. |
| `"slideshow"` | Вставка блока `<div class="svodka-carousel">` с горизонтальной лентой всех фото после второго `</p>`. |
| `"cover_only"` | HTML возвращается без изменений — все фото только обложка. |

HTML-атрибуты экранируются через `html.escape()`.

#### Интеграция

- **`web_researcher.py`**: после сборки `all_images` вызывается
  `await filter_and_deduplicate_web_images(all_images)` — в `WebResearchReport` передаются
  только `clean_images`.
- **`lab_pipeline.py`** (`run_cluster_generate_step`): шаг «Injection» выполняется после
  `_inject_internal_links` и до `_ensure_sources_block`:
  ```python
  html_with_images = inject_article_images(html_with_links, body_images, layout=image_layout)
  ```
  Параметр `image_layout` приходит из формы Лаборатории (Step 3).
- **`app/api/dashboard.py`**: `lab_cluster_generate_partial` принимает
  `image_layout: Annotated[str, Form()] = "inline"` и передаёт его в сервис и шаблон.

#### UI

- В Шаге 3 Студии добавлен селектор «📸 По тексту статьи», «🎠 Слайдшоу», «🖼️ Только обложка».
- В карточке результата генерации отображается бейдж выбранного режима.

### 1.13 Фильтрация рекламных агрегаторов, тёмных экранов и потоковое видео (v2.37.0)

- **Блокировка Telegram-агрегаторов (`_AGGREGATOR_DOMAINS`)**: `tvgram.ru`, `tgstat.ru`, `telemetr.io` и аналоги исключены из ресерча и медиа-выборок (их картинки — промо-скриншоты каналов).
- **Детекция тёмных/монохромных рекламных плашек**:
  - `MIN_MEAN_BRIGHTNESS = 28.0` — отсечение почти чёрных заставок.
  - Проверка `dark_ratio > 0.65` и `white_ratio > 0.65` — отсечение карточек с заливкой фона и логотипом по центру.
- **Интерактивный просмотр изображений (Lightbox)**: клик по фото в Студии открывает оригинальный файл через безопасный серверный прокси `/api/ui/lab/media/web-image?url=...` в новой вкладке.
- **Потоковое видео по требованию (`/api/ui/lab/media/video/{post_id}`)**:
  - В карточке медиа встроен полнофункциональный плеер `<video controls preload="metadata">`.
  - Эндпоинт отдает кэшированный MP4 с диска (`storage/media/telegram/{post_id}.mp4`) или скачивает его по требованию через MTProto Telethon с заголовками `video/mp4`.
  - Сохранена кнопка «⬆️ Загрузить в VK Video» для экспорта на внешний видеохостинг.
- **Контроль соответствия событий (Event Mismatch Guard)**:
  - Список `_CRITICAL_EVENT_STEMS` (пожары, ДТП, суды, атаки БПЛА).
  - Запрет привязки сторонних региональных новостей (например, о кулинарии/туризме) к трагическим происшествиям по одному лишь совпадению названия области.
- **Строгая релевантность перелинковки**: запрет ссылок из `voennye-novosti` и `chp-i-proisshestvij` в невоенных материалах; минимум 2 общих стемма для межкатегорийных ссылок.

### 1.14 ИИ-валидация релевантности медиа и отсечение оффтопика (`image_cleaner.py`, `web_researcher.py`) (v2.38.0)

- **Селективный парсинг в `fetch_clean_article`**:
  - Исключен жадный full-page XPath.
  - Извлекаются только целевые обложки (`og:image`, `twitter:image`) и семантические блоки `<article>//figure//img` / `<main>//figure//img` (максимум 3 на страницу) с предварительным отсевом аватаров, иконок и презентеров.
- **ИИ-арбитр (`verify_images_with_ai`)**:
  - Кандидаты проверяются через модель (цепочка `arbiter` / Gemini) в контексте заголовка и фактов новости.
  - Автоматическая отбраковка: телеведущие/дикторы в студии, спортивные матчи/футболисты, случайный автотрафик, кулинария/рецепты, сторонние баннеры.
  - Fast-path фильтрация `_OFFTOPIC_URL_HINTS` для мгновенного отсева очевидных ключевых слов в URL и заголовках без траты токенов.
  - Отображение в Студии медиа: бейдж `🟢 ИИ: Одобрено` для релевантных иллюстраций и сворачиваемый блок `🚫 Отклонено ИИ как оффтопик ([N])` с причинами отсева.

### 1.15 Авторизация VK Video и сообщества ВКонтакте через браузерную сессию (`vk_video_service.py`) (v2.45.0)

- **Модель `VKVideoConfig`**:
  - Хранится в `system_settings` по ключу `vk_video_config` с шифрованием Fernet как для `encrypted_access_token`, так и для браузерной сессии `encrypted_storage_state`.
- **Нормализация и выпуск токена (`normalize_vk_storage_state`, `probe_vk_browser_session`)**:
  - Принимает экспорт кук из браузерного расширения `Cookie-Editor` (JSON-массив) или Playwright `storage_state.json`.

### 1.15 Двухуровневый сбор фото Telegram и каскадный резолвер обложек (`content_worker.py`, `dashboard.py`, `backfill_article_covers.py`, v2.47.0)

## 2. Запланировано (в коде отсутствует)

### 2.1 Разрешение владельца на медиа с водяным знаком (Фаза 3)

Из `PROJECT.md` 2.3: приоритет — чистые медиа; если чистого нет, то либо
генерация, либо **владелец разрешает** использовать медиа со знаком.

Детектор и генерация есть, переключателя разрешения нет. Сейчас изображение с
большим покрытием отбрасывается безусловно, и при пустом ключе генератора
статья остаётся без картинки вовсе — хотя оператор мог бы разрешить исходник.

Нужно: флаг в настройках, третий исход в выборе обложки, отражение решения в
журнале прогона.

### 2.2 Ручная проверка медиа (Фаза 2)

Из `PROJECT.md` 2.2: владелец видит, какие медиа есть и как система их
отфильтровала, до публикации. Основа готова: страница «Лаборатория» и
`pipeline_inspection.py` качают фото и показывают вердикт по каждому — чистое,
обрезаемое, отброшенное, не проверялось, с текстом OCR и покрытием. Не хватает
шага одобрения: сейчас это отчёт, а не остановка.

### 2.3 Дожатие середины (не приоритет)

Инпейнтинг помеченного участка. Осознанно отложено: текущий путь закрывает два
исхода, которые важны (обрезать лёгкую плашку, перегенерировать тяжёлую), а
инпейнтинг — улучшение середины и публикацию не блокирует.
