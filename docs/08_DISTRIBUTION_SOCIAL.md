# 08_DISTRIBUTION_SOCIAL.md — Распространение в соцсетях

Telegram, ВКонтакте, Одноклассники и Дзен. Это второй этап после публикации на
сайте: главная ссылка рождается в WordPress, поэтому соцсети не могут быть
первым шагом.

**Как читать этот файл.** «Реализовано» описано по коду. «Запланировано» —
намерение из `PROJECT.md`, в коде отсутствует. При расхождении верить коду.

Файлы: `app/services/social_base.py`, `social_telegram.py`, `social_vk.py`,
`social_ok.py`, `social_dzen.py`, `app/workers/publisher_worker.py`.

---

## 1. Реализовано

### 1.1 Общий контракт (`social_base.py`)

Все адаптеры реализуют один интерфейс: на вход статья и ссылка на WordPress, на
выходе `PublishResult` — внешний идентификатор, ссылка, число попыток, ошибка.
Это позволяет добавлять площадки без переписывания воркера.

Общие бесплатные преобразования:

- HTML → обычный текст;
- тизер с обрезкой по границе слова;
- до 5 хештегов из SEO-ключей; при пустом наборе — `#новости #сводка`.

У площадки без настроек адаптер возвращает `SocialNotConfiguredError`. Воркер
считает это **пропуском, не ошибкой статьи**: пустой ключ не должен ронять уже
живой сайт.

### 1.2 Telegram (`social_telegram.py` и `telegram_connection.py`)

Обычный HTTP Bot API, методы `sendPhoto` и `sendMessage`. Управление токеном и каналом осуществляется через базу данных (`SystemSetting['telegram_channel_config']`) с Fernet-шифрованием либо через `.env`.

| Параметр | Значение |
| --- | --- |
| Подпись к фото | 1024 единицы UTF-16 |
| Обычное сообщение | 4096 единиц UTF-16 |
| Попыток | 3 |
| Таймаут | 30 секунд |
| Максимальный `retry_after` | 30 секунд |

Длина считается в UTF-16, а не `len()` Python — эмодзи в Telegram занимают две
единицы. Подпись: жирный заголовок, тизер, хештеги и ссылка «Читать полностью».
Если есть безопасный HTTPS-адрес, ссылка переносится в кнопку; тогда в самом
тексте она не дублируется.

Допустимый HTML Telegram сохранён (жирный, курсив, подчёркивание, зачёркнутый,
ссылка, код, цитата); остальной снимается. Живая диагностика (`probe_telegram_bot_connection`) проверяет доступность бота (`getMe`), существование канала (`getChat`) и наличие прав администратора с разрешением публикации (`getChatMember: can_post_messages`).

### 1.3 ВКонтакте (`social_vk.py`)

HTTP API, `wall.post`, публикация от имени сообщества (`from_group=1`),
отрицательный `owner_id` группы.

- Формат лонгрида до 3800 символов: содержательный структурированный материал из 3–5 абзацев фактуры из статьи, без искусственного усечения до одной фразы.
- Прикрепление фото-обложки: при использовании токена сообщества (`vk1.a.*`), где стандартный метод `photos.getWallUploadServer` запрещен API ВКонтакте (ошибка 27), в `attachments` передается канонический URL статьи WordPress (`wp_post_url`). Стена ВКонтакте нативно считывает OpenGraph метатеги (`og:image`, `og:title`) и разворачивает полноценную полноразмерную фото-карточку со сниппетом и обложкой материала. При наличии пользовательского токена поддерживается нативная прямая загрузка фото через `photos.getWallUploadServer`.
- При наличии видео первым вложением идет VK-видео, затем фото-обложка или сниппет статьи.
- В конце записи формируются: прямая кликабельная ссылка на полный материал на сайте (`👉 Читать полностью на сайте:`), призыв подписаться на официальный Telegram-канал (`⚡️ Оперативные сводки в Telegram:`), нативный блок спонсора FreeAPI AI (`💡 Партнёр рубрики — FreeAPI AI: ...`) и аккуратные короткие хештеги.
- Поддерживаются как пользовательские токены (Kate Mobile `client_id=2685278`), так и ключи доступа сообщества (`vk1.a.*`).
- 3 попытки, таймаут 30 секунд, экспоненциальный отступ до 20 секунд.

### 1.4 Одноклассники (`social_ok.py`)

HTTP API, `mediatopic.post`. Публикация — компактное JSON-вложение: текст,
фото и ссылка. Текст до 800 символов.

Подпись API считается точно по контракту: убрать `access_token` и `sig`,
отбросить `None`, отсортировать остальные пары по ключу, склеить как
`ключ=значение` без разделителей, прибавить секрет, взять MD5. Если отдельный
секрет сессии пуст, `derive_session_secret` умеет получить его как
`MD5(access_token + application_secret_key)`.

### 1.5 Дзен (`app/services/dzen_publisher.py` и `social_dzen.py`)

Поддерживаются **два режима публикации** с автоматическим выбором наиболее надежного:

1. **Браузерная публикация Playwright Stealth (Основной режим, `dzen_publisher.py`)**:
   - Авторизация через сохраненную сессию (`storage_state.json`, Playwright cookies + localStorage) без передачи логина и пароля.
   - **Автоматическая нормализация кук (`normalize_dzen_storage_state`)**: преобразование Chrome Extension экспортов (`sameSite: "no_restriction"` -> `"None"`, `expirationDate` -> `expires`), отсечение несовместимых ключей.
   - Шифрованное хранение сессии в базе данных PostgreSQL (`system_settings` -> `dzen_browser_session`) с шифрованием Fernet.
   - Живая диагностика валидности сессии (`probe_dzen_session`) с переходом в Студию канала (`https://dzen.ru/profile/editor/{channel_name}`), проверкой наличия `Session_id` Яндекса, кнопки «Войти» и защиты SmartCaptcha.
   - **1-Click создание тестового черновика** (`POST /api/ui/settings/dzen/test-publish`) из панели настроек для безопасной проверки интеграции без публикации в живую ленту.
   - **Публикация из Лаборатории (Шаг 4)**: кнопка «📱 В Дзен» (`POST /api/ui/lab/cluster/{cluster_id}/publish-dzen`) с поддержкой черновиков и боевой ленты.
   - **Раздельная реклама**: функция `inject_dzen_promo` позволяет внедрять в статьи Дзена нативные промо-блоки, callout-врезки или партнерские ссылки, оставляя сайт `svodka.press` со стандартными баннерами.
   - **Нативная вставка разметки через ClipboardEvent**: замена устаревшего `insertHTML` на синтетическое событие `ClipboardEvent('paste')` с `DataTransfer` (`text/html` + `text/plain`). Это активирует парсер React Draft.js Дзена, гарантируя создание нативных блоков заголовков H2/H3, жирного и курсивного начертаний, активных кликабельных ссылок `<a>`, стилизованных блоков внимания `<blockquote>` и адаптивных галерей изображений `<figure><img>` с авто-загрузкой на CDN Дзена.
   - **Двухэтапная точная вставка обложки (React SelectionState Sync)**:
     - В Draft.js манипуляция DOM `window.getSelection()` игнорируется внутренним состоянием React. Для гарантированного размещения фото-обложки на самом верху статьи (над первым абзацем):
       1. Сначала вставляется тело статьи через `ClipboardEvent('paste')`.
       2. Редактор принудительно прокручивается наверх (`window.scrollTo(0, 0)`).
       3. Выполняется физический клик Playwright в верхний левый угол первого блока (`first_block.click(position={"x": 5, "y": 5})`), что генерирует синтетические события React и переводит фокус Draft.js на верхний блок.
       4. Нажимаются клавиши `Home` -> `Enter` -> `ArrowUp`, создавая пустую строку в самом начале тела.
       5. Через `ClipboardEvent` вставляется `<figure><img src="{cover_url}" alt="{title}" /></figure>`.
       6. Ожидание не менее 6 секунд позволяет фоновому процессу Дзена скачать внешнее изображение и преобразовать его в нативный ассет CDN (`avatars.dzeninfra.ru/get-zen_doc/...`).
   - **Официальная обложка в ленте канала (`smart_crop_516x290`)**:
     - Дзен автоматически назначает первую фотографию статьи главной обложкой карточки материала в ленте канала (`content--zen-image-cover__image-2x`), отображая полноценную фотокарточку в рекомендательной ленте `https://dzen.ru/{channel_name}`.
    - **Автоматизация диалогов публикации (`_trigger_publish`)**:
      - Снятие обучающего оверлея справки редактора (`.article-editor-desktop--help-popup__overlay-3q`).
      - Клик по кнопке публикации в шапке редактора: `button[data-testid="article-publish-btn"]` (`force=True`).
      - Автоматическое снятие галочки «Опубликовать позже» (если чекбокс активен), переводящее кнопку модального окна из режима отложенной публикации в прямую немедленную публикацию.
      - Клик по кнопке модального окна `button[data-testid="publish-btn"]` (`type="submit"`).
      - Авто-прохождение VK SmartCaptcha: обнаружение фрейма `https://id.vk.ru/not_robot_captcha` через `page.frames`, клик по чекбоксу `#not-robot-captcha-checkbox` (`input[type="checkbox"]`).
      - Ожидание ухода со страницы редактора и подтверждение боевого постоянного URL статьи (`https://dzen.ru/a/{pub_id}`).
      - **Пакетная публикация черновиков (`scripts/publish_dzen_drafts.py`)**: автономный скрипт для пакетного обхода всех накопившихся черновиков (`?state=draft`) с поиском ссылок `a[href$="/edit"]`, их открытием и автоматическим переводом в статус live.
    - **Точная каноническая ссылка**: в подвал статьи Дзена внедряется активная ссылка на первоисточник на сайте `svodka.press`. Адрес определяется строго по живому ответу WordPress REST API (`wp_stat["url"]`) или канонической структуре `https://svodka.press/{category}/{slug}/` с транслитерированным slug без кириллицы.
    - **Fallback для обложки без ключей WordPress**: если WP Application Password не настроен в `.env`, обложка извлекается из `article.platform_statuses['wp']['cover_url']`.

2. **HTTP API (`social_dzen.py`, Резервный режим)**:
   - Партнерский API `dzen.ru/api/v3/publisher` с авторизацией по `OAuth` токену из `.env` (если браузерная сессия не загружена).
   - Два шага: создание публикации (`/publication`), затем подтверждение (`/publish`).

Перед отправкой тело в обоих режимах приводится к разрешённому набору: `p`, `h2`, `h3`, списки,
жирный/курсив, ссылки, цитаты, `figure`, `img`, `figcaption`. `h1` становится
`h2`, h4–h6 становятся `h3`; опасные блоки и inline-атрибуты вырезаются.
Обязательно сохраняется каноническая ссылка на первоисточник на сайте, исключающая поисковую конкуренцию.

| Параметр | Значение |
| --- | --- |
| Заголовок | до 120 символов |
| Описание | до 500 символов |
| Режимы создания | Публикация / Черновик |
| Форматы рекламы Дзена | Нативный баннер / Callout box / Custom HTML / Без рекламы |
| Таймаут браузера | 30 секунд |

### 1.6 Браузерные соцсети (`social_browser_publisher.py`)

По аналогии с Яндекс Дзеном и ВКонтакте, следующие 6 площадок подключаются через
авторизованную браузерную сессию (`Cookie-Editor` JSON-экспорт / Playwright
`storage_state`), зашифрованную Fernet в `system_settings` (`key = "social_browser_sessions"`):

| Площадка | Enum | Домен кук | Лимит символов | Особенности публикации |
| --- | --- | --- | --- | --- |

| **TenChat** (`https://tenchat.ru/`) | `Platform.TENCHAT` | `.tenchat.ru` | 2500 | Запись в веб-студии (`/editor`) с авто-закрытием обучающих модалов («Далее» $\to$ «Приступить»), заполнением заголовка, Quill-редактора, выбором тематики и загрузкой обложки |
| **Threads** (`https://www.threads.com/`) | `Platform.THREADS` | `.threads.com` / `.threads.net` | 480 | Ветка с авто-зеркалированием кук `.threads.net` $\leftrightarrow$ `.threads.com`, фото и ссылкой |
| **Facebook** (`https://www.facebook.com/`) | `Platform.FACEBOOK` | `.facebook.com` | 1800 | Пост на Страницу/в группу (`c_user`, `xs`) с фото-обложкой и ссылкой |
| **Pinterest** (`https://ru.pinterest.com/`) | `Platform.PINTEREST` | `.pinterest.com` | 480 | Фото-пин через `/pin-creation-tool/` с заголовком, SEO-описанием и целевой ссылкой на статью |
| **YouTube Сообщество** (`https://www.youtube.com/`) | `Platform.YOUTUBE` | `.youtube.com` / `.google.com` | 1400 | Текстовый пост с картинкой во вкладке «Сообщество» (`/community` / `/posts`) канала; авто-прохождение Google Cookie Consent (`consent.youtube.com`, кнопка «Принять все») |
| **Spark.ru** (`https://spark.ru/`) | `Platform.SPARK` | `.spark.ru` | 8000 | Публикация в блог стартапа Svodka Press (`https://spark.ru/startup/svodka-press`): селектор таргета `44324`, заголовок, лид, Editor.js тело, теги, обложка через `#transportInput` |

Все 6 адаптеров (`SetkaBrowserAdapter`, `TenChatBrowserAdapter`,
`ThreadsBrowserAdapter`, `FacebookBrowserAdapter`, `PinterestBrowserAdapter`,
`YouTubeCommunityBrowserAdapter`) наследуют `BaseSocialAdapter` и вызываются
параллельно в `publisher_worker.py` (`build_adapters` $\to$ `_fan_out`). 

**Способы авторизации и архитектура сессий:**
- **In-Page TenChat SMS Flow (`app/services/tenchat_auth.py`)**: прямое получение СМС Sber ID из веб-интерфейса `/settings`. Запуск headless Chromium на VPS, ввод номера, получение 5-значного кода и фиксация доверенного устройства в PostgreSQL.
- **Persistent Profile & SSH SOCKS5 Tunnel (`scripts/remote_login_browser.py`)**: запуск полноценного графического Chromium на машине оператора с маршрутизацией всего сетевого трафика через IP VPS (`144.31.141.17`) через динамический SOCKS5 порт 1085. Автоматически перехватывает авторизацию Google (YouTube `@svodkapress`) и TenChat, валидирует ключи сессии (`LOGIN_INFO`, `SAPISID`, `SID`, доступ к `/editor`) и синхронизирует состояние в базу PostgreSQL без искажений TLS/OSCrypt.
- **Архитектура изоляции воркеров**: Gunicorn веб-приложения на VPS настроен на 1 рабочий процесс (`--workers 1`), что исключает потерю контекста в памяти при интерактивных multi-step сценариях (отправка СМС $\to$ ввод кода).
- **Диагностика**: В панели `/settings` доступны кнопки «⚡ Проверить» (`POST /api/ui/settings/social-browser/{platform}/probe`), статус в реальном времени (`🟢 Активен` / `⚠️ Требуется вход`) и тестовая публикация (`POST /api/ui/settings/social-browser/{platform}/test`).


### 1.7 Порядок, частичный провал и повторы (`publisher_worker.py`)

WordPress публикуется **первым и один**. Соцсети затем идут **параллельно**
через `asyncio.gather` с изоляцией сбоев: падение одного адаптера не отменяет
остальные, и каждая площадка получает свой результат.

`platform_statuses` — JSONB-карта с состоянием каждой площадки:
`pending`, `published`, `disabled`, попытки, внешний id, ссылка, ошибка, время.
Счётчик растёт только при неуспехе. Уже опубликованная площадка пропускается;
после частичного сбоя повтор безопасно доделывает только недостающую.

| Параметр | Значение |
| --- | --- |
| Статей за проход | 5 |
| Попыток на статью | 5 |
| Попыток WordPress внутри статьи | 3 |
| Попыток внутри адаптера | 3 |
| Отступ WordPress | 2 с, множитель 3, максимум 60 с |
| Расписание | минуты 5, 15, 25, 35, 45, 55 |

Если WordPress не вышел — статья `FAILED`, соцсети не трогаются. Если сайт
вышел, но часть соцсетей нет — `PARTIAL`, задача автоматически **не**
повторяется, чтобы не рисковать вторым постом на сайте. Оператор должен
запустить повторное распространение вручную. Кнопки такого действия в панели
сейчас нет — см. раздел 2.

## 2. Запланировано (в коде отсутствует)

### 2.1 OAuth для социальных площадок (Фаза 5)

Утверждено владельцем: соцсети подключаются через **OAuth**, а не ручным вводом
долгоживущих токенов.

Сейчас OAuth-flow **нет**. Все адаптеры принимают значения из `.env` или
зашифрованных браузерных сессий в `system_settings`:
Telegram bot token, VK access token / сессия, OK token/key/secret, Dzen
браузерная сессия, а также браузерные сессии Сетки, TenChat, Threads, Facebook,
Pinterest и YouTube. Слово `OAuth` у Дзена и Метрики — это префикс готового
токена в HTTP-заголовке, не авторизация через редирект, согласие владельца,
code exchange и refresh token.

Нужен общий механизм в панели:

1. «Подключить площадку»;
2. редирект на страницу площадки;
3. возврат с кодом;
4. обмен кода на access/refresh токены;
5. шифрованное хранение и обновление токена;
6. явный статус: подключено / истекает / требует повторного входа.

Telegram — отдельный случай: пользовательский Telegram-аккаунт уже подключается
через номер, код и 2FA; это не OAuth. В дальнейшем нужно отдельно решить,
нужен ли Bot API для распространения или публикация идёт от пользовательского
аккаунта в свой канал.

### 2.2 Переписывание под каждую площадку (Фаза 5)

Сейчас текст **не переписывается** отдельной LLM-задачей. Каждый адаптер
форматирует тизер, заголовок, хештеги и ссылки под лимиты конкретной площадки.

Цель: отдельный текст под Telegram, ВК, ОК, Дзен и последующие модули — с
ограничениями, голосом и формой конкретной площадки. В ручном режиме владелец
видит и одобряет каждый вариант.

### 2.3 Панель распространения (Фаза 5)

Нужны: OAuth-подключение, вкл/выкл площадок, статус токена, редактор варианта
поста, ручная кнопка «распространить повторно» для статьи `PARTIAL`, журнал
попыток на каждую площадку.

## 3. Проверки этого модуля

```bash
pytest tests/test_social_browser_publisher.py tests/test_social_adapters.py tests/test_publisher_worker.py
```

Тесты проверяют нормализацию кук (включая зеркалирование `.threads.net` $\leftrightarrow$
`.threads.com` и `.google.com` $\to$ `.youtube.com`), шифрование Fernet в
`system_settings`, лимиты подписей, вложения, вручную посчитанную подпись ОК и
изоляцию ошибок всех 10 площадок дистрибуции.
